# EconoCausal: Dynamic Pricing Using Double Machine Learning

## Project Overview

EconoCausal is a data science project exploring dynamic pricing using Double Machine Learning (DML). This repository includes retail transaction data preparation, exploratory data analysis (EDA), candidate product selection, product-month panel construction, and data validation.

The current data engineering workflow uses the UCI Online Retail II dataset to prepare transaction-level sales data and construct a monthly panel for selected products. The panel provides a structured starting point for further pricing and causal analysis.

## Setup

Run the following commands from the repository root in Windows PowerShell.

Create and activate a virtual environment:

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
```

Install the project and development dependencies:

```powershell
python -m pip install -e ".[dev]"
```

## Run the Data Pipeline

Run:

```powershell
python -m econocausal.data.run_pipeline
```

The pipeline has three stages:

1. **Build prepared sales dataset** - filters excluded transactions and writes a processing report.
2. **Build candidate product-month panel** - aggregates selected products by month.
3. **Validate candidate panel** - checks duplicate product-month keys, missing calendar months, and missing or nonpositive core numeric values.

### Generated Outputs

| Output | Description |
|---|---|
| `data/processed/retail_sales.csv` | Prepared transaction-level sales data |
| `data/processed/sales_dataset_report.txt` | Dataset preparation counts and report |
| `data/processed/candidate_product_month_panel.csv` | Monthly panel for four candidate products |

Generated data files should remain local and should not be committed unless explicitly required by the project.

## Data and Research Limitations

- The panel contains four selected products and should not be interpreted as representative of the entire retail dataset.
- Observed price changes are descriptive and do not establish that price changes caused changes in demand or revenue.
- The current pipeline prepares data for downstream analysis; it does not, by itself, estimate causal effects or produce an optimized pricing policy.
- Missing customer IDs and duplicate transaction rows are retained by the sales dataset builder. Their treatment should be considered explicitly in subsequent analyses.
